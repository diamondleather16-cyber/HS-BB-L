HS-BB-L V64.6 / 台帳を「操作確定優先」に修正

1. 削除を tombstone（削除記録）を最優先する仕様に変更。
   - GitHub側に古い手入力試合が残っていても削除記録があれば復活しない。
   - 保存時に削除済み manual_match / override / team_link を物理的にも除去。

2. 手入力専用バックアップにも deleted_matches を保存。
   - 旧V64.5は manual_matches だけを別バックアップしていたため、削除後に古いバックアップが復元側へ混ざる余地があった。
   - V64.6では「追加」と「削除」を一組で端末保存する。

3. 削除操作をGitHub再読込で検証。
   - 削除後、GitHub commitの deleted_matches に対象キーが存在するか確認。
   - 手入力試合の場合、GitHub manual_matches からも消えているか確認。
   - 確認できた時だけ「GitHub照合済み」と表示。

4. 単件削除・一括削除の両方を同じ経路に統一。

5. 読込・マージ時にも削除記録を最優先。
   - GitHub main / raw / Pages / 端末ミラー / 手入力バックアップのどこに古い行があっても、削除記録が勝つ。

6. 既存V64.5の手入力バックアップは移行読み込み対応。
